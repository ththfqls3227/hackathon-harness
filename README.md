# Hackathon Harness

문제 정의, 범위 선택, 구현, 검증과 작업 내용 이해를 짧게 연결하는 한국어 Codex 하네스입니다. 기본 스킬 4개와 선택 스킬 4개, 프로젝트 진입 스킬 등록 도구, 로컬 CSV 점검 도구를 제공합니다. MIT 라이선스이며 미리 만든 정답이나 특정 앱 템플릿은 포함하지 않습니다.

실행기·MCP·전역 설정 설치 없이 문서를 읽어 시작합니다. 선택적인 프로젝트 스킬 등록과 CSV 도구는 Python 3.10+가 필요합니다(실행 검증: Python 3.11). 등록 도구는 macOS·Linux의 POSIX 파일 기능을 사용하며, 미지원 환경은 START.md 직접 읽기로 사용합니다. 역할 카드는 자동 등록되는 에이전트 설정이 아닙니다.

아래 명령의 `python3.11`은 검증에 사용한 실행 파일명입니다. 제공 환경에서는 `python3 --version` 등으로 확인한 Python 3.10 이상 실행 파일명으로 바꿔 사용합니다. 시험 환경의 Python을 이 문서 때문에 업데이트하지 않습니다.

## 시작

현재 응시 프로필은 **제공된 Codex 전용**입니다. 시작·재개와 개별 스킬 실행 전에 [응시 규정 프로필](docs/exam-contract.md)을 읽습니다. 일반 체험 튜토리얼에 Claude가 나오거나 MCP 탭이 보이더라도 해당 사용의 허용 여부는 시험별 안내로 판단합니다.

최신 재시험 가이드의 응시 창은 **2026-11-05 19:00~23:00 KST**, 준비 권장 시각은 **18:40**입니다. 참가자의 실제 응시·완료 상태는 확인되지 않았습니다. **제공된 Codex만 사용하고 업데이트하지 않습니다.** Astra는 사용하지 않으며 권장 모델 표시명은 **6.1 Sol, 6.0 Sol, 5.6 Terra, 6.0 Luna**입니다. 일반 Computer Use는 금지됩니다. 직접 만든 웹사이트의 Playwright 검증은 이전 사용자 전달 허용 범위이므로, 현재 과제·운영 안내에서 그 범위를 다시 확인한 경우에만 [응시 규정](docs/exam-contract.md)에 따라 사용합니다.

먼저 실제 과제 안내에서 공개 저장소 다운로드와 지침·스킬 사용을 허용하는지 확인합니다. 파일·Skill 업로드 차단과 공개 저장소 다운로드 허용은 서로 다른 조건이며, 공개 자료라고 자동으로 허용되는 것은 아닙니다. 충돌하거나 불명확하면 플랫폼 지원 담당에게 확인하고, 차단을 다른 반입 경로로 우회하지 않습니다.

허용된 경로로 저장소를 가져온 뒤, **실제 과제의 작업 폴더에서** 제공된 Codex를 실행합니다. 아래 요청의 경로를 실제 경로로 바꿔 입력합니다.

제공된 Codex가 다운로드부터 진행하게 하려면 다음처럼 요청할 수 있습니다.

> 공개 저장소 `https://github.com/ththfqls3227/hackathon-harness`의 `v0.5.0`을 실제 과제 폴더 안 `tools/hackathon-harness`에 clone해. 같은 폴더가 있으면 보존하고 먼저 확인해. 그 안의 `START.md`를 읽고 이 과제에 적용해. 환경에서 지원되면 `scripts/setup_project.py`로 프로젝트 진입 스킬도 등록하고, 지원되지 않으면 파일을 직접 읽는 방식으로 이어가.

과제 작업 폴더에서 공개 저장소 다운로드가 허용되는 경우:

```sh
git clone --depth 1 --branch v0.5.0 https://github.com/ththfqls3227/hackathon-harness.git tools/hackathon-harness
```

같은 이름의 폴더가 이미 있으면 내용을 덮어쓰지 않고 기존 자료를 먼저 확인합니다. 태그로 버전을 고정하며 시험 중 최신 버전으로 자동 업데이트하지 않습니다.

제공 Codex에 다음처럼 요청하면 바로 시작할 수 있습니다.

> `tools/hackathon-harness/START.md`를 읽고 이 과제에 적용해. 실제 과제 지침과 현재 응시 규정을 우선해. 현재 단계·작업 루트·필수 결과물·남은 시간을 짧게 확인하고, 문제 정의부터 구현·검증까지 필요한 작업을 이어가.

이 명시적 읽기는 이미 허용된 경로로 작업 공간 안에 가져온 문서를 읽는 방법입니다. 개인 PC 파일 반입이나 Skill 업로드 차단을 우회하는 방법이 아닙니다. 별도 설치, API 키, MCP, Codex 업데이트가 필요하지 않습니다. 기존 과제의 README·AGENTS.md·설정을 덮어쓰지 않습니다.

### 프로젝트 스킬로 등록하기

반복해서 부르려면 과제 작업 폴더에서 다음 명령을 사용합니다. `python3.11`은 제공 환경에 이미 있는 Python 3.10+ 실행 파일명으로 바꿉니다. 없으면 위의 직접 읽기 방식으로 사용하고 환경을 업데이트하지 않습니다.

```sh
python3.11 tools/hackathon-harness/scripts/setup_project.py --project .
python3.11 tools/hackathon-harness/scripts/setup_project.py --project . --apply
```

첫 명령은 변경 없이 확인하고, 두 번째는 **과제 폴더의 `.agents/skills/hackathon-harness/SKILL.md` 한 개만** 만듭니다. 기존 AGENTS.md·설정·다른 스킬을 수정하지 않습니다. 같은 내용이면 아무것도 바꾸지 않고, 다른 내용이나 심볼릭 링크가 있으면 덮어쓰지 않고 종료합니다. 하네스 clone은 과제 폴더 안에 있어야 합니다.

과제 폴더에서 실행한 제공 Codex의 `/skills`에 보이면 **`$hackathon-harness`**로 시작·재개합니다. 현재 공식 문서는 `.agents/skills`의 변경 감지를 안내하지만 제공된 고정 버전에서도 동일하게 작동한다고 보장하지 않습니다. 목록에 없으면 START.md를 직접 읽습니다. 이 등록은 스킬 사용 지침 연결이며 로딩·실제 실행을 확인한 증거는 아닙니다.

원본 스킬만 과제 폴더로 복사하면 내부 상대경로가 달라질 수 있어 진입 파일이 clone 안의 원본 문서를 읽습니다. clone 위치를 옮기면 연결도 다시 확인해야 합니다. 기존 진입 파일이 충돌하면 직접 읽기로 계속하며 자동 삭제·강제 업데이트는 하지 않습니다. 추가 파일이 제출 범위에 포함되는지도 실제 안내로 확인합니다. [공식 스킬 탐색 방식](https://learn.chatgpt.com/docs/build-skills).

역할 카드는 사람이 읽거나 지원되는 에이전트에 전달하는 지침입니다. 파일이 존재한다고 subagent가 생성되거나 특정 모델로 실행되는 것은 아닙니다. 기본은 하나의 Codex가 순서대로 진행하는 방식입니다.

v0.2.0은 CodexClaw에서 참고한 계획·사전 검토·구현·검증·정리 흐름, 조건부 경로의 실행 확인, 과제 안의 기록을 이용한 재개를 기존 스킬에 반영했습니다. 작은 수정에는 전체 절차를 강제하지 않습니다. [반영 범위와 제외 이유](docs/codexclaw-review.md)를 확인하세요. CodexClaw 플러그인 설치나 자동 상태 전환 기능은 포함하지 않습니다.

v0.3.0은 응시 규정 프로필을 모든 스킬·역할의 시작점에 연결했습니다. 공개 도구의 허용된 수신과 시험 자료 반출을 구분하고, 화면 캡처 요청·Claude 실행·키 출력·제출 확정 후 작업을 하지 않도록 명시했습니다. 스크린샷에 메뉴가 보인 사실만으로 CLI 실행·MCP 연결·실제 시험 호환성을 검증했다고 주장하지 않습니다.

v0.3.1은 개인별 접속 안내 메일을 반영해 권장 모델과 업데이트 금지, 09:40 추가 공지·10:00 시작·14:00 종료, 입력기·감독 앱·Wi-Fi, 공개 유지와 장애 접수 기준을 보강했습니다. 권장 모델을 허용 모델 전체 목록으로 바꾸거나 사용량을 임의의 점수 공식으로 해석하지 않습니다. 개인 응시 링크와 메일 원문은 포함하지 않습니다.

v0.4.0은 프로젝트 진입 스킬·START.md·자체 웹 Playwright 검증·장애 후 재개를 연결하고 재시험 시각을 과거 일정과 분리했습니다. 원본 플러그인 전체나 개인 전역 설정을 설치하지 않습니다. 상세 시험 내용은 준비 저장소에 포함하지 않습니다.

v0.5.0은 [task-understanding](.agents/skills/task-understanding/SKILL.md)을 더해 실제 과제 지침과 허용된 화면 텍스트에서 작업 단계의 모든 필수 서술 산출물을 찾고, 실제 코드·테스트에 근거해 작성하도록 안내합니다. 주요 결정·기능 뒤에는 1~2개씩, 제출 전에는 우선순위 높은 질문 3~5개를 기본으로 참가자가 먼저 설명하게 합니다. 후속 문항·점수를 예측하거나 답안을 미리 만들지 않으며 제출물 확정 뒤에는 AI 작업을 중단합니다. 재시험의 최신 가이드 일정과 운영 조건도 [응시 규정](docs/exam-contract.md)에 반영했습니다.

## 선택 기능 사용

START.md에서 task-flow로 시작하고, 실제 과제에 맞는 스킬만 추가로 읽습니다.

- 작업 단계에 필수 서술 문서가 있거나 구현 선택을 참가자가 설명할 필요가 있으면 task-understanding을 읽습니다. 실제 README·로컬 지침·참가자가 허용 범위에서 텍스트로 전달한 화면 요구를 대조해 문서 수를 정하고, 현재 작업 공간의 코드·테스트·대화·명령 기록 중 허용된 근거만 사용합니다. 기록이 없으면 추측하지 않습니다.
- CSV가 있으면 data-check로 구조를 확인합니다. 업무 규칙과 성과 분석은 별도로 해야 합니다.
- 화면이 필요하면 ui-review로 정상·빈 데이터·실패 상태를 검토합니다. 현재 과제·운영 안내에서 Playwright 대상 범위가 확인된 직접 만든 웹에만 web-verify를 적용합니다. 확인되지 않았거나 도구가 없으면 기존 검사와 참가자의 수동 확인을 이어갑니다.
- 설비나 시스템의 관계를 설명해야 하면 system-diagram을 사용합니다. 원본 Anatomy의 키트나 고급 렌더러가 포함된 것은 아닙니다.

예를 들어 작업 중인 과제의 Codex에 다음처럼 요청합니다.

> `tools/hackathon-harness/.agents/skills/task-understanding/SKILL.md`를 읽고, 이 과제의 작업 단계에서 요구하는 서술 산출물을 모두 확인해. 실제 코드·테스트로 확인되는 내용만 초안에 반영하고, 내가 결정한 내용은 구분해. 큰 결정이나 기능을 마친 뒤 내가 먼저 설명할 질문을 1~2개씩 해 줘.

CSV 점검 예시도 **과제 작업 폴더에서** 실행합니다. 데이터와 결과를 공개 하네스 폴더 안에 두지 않습니다.

```sh
python3.11 tools/hackathon-harness/.agents/skills/data-check/profile_csv.py --input ./input.csv --output ./profile.json
```

기존 결과를 덮어쓰지 않습니다. 종료 코드는 정상 0, 열 너비 오류가 있는 보고서 1, 입력·출력·문법 오류 2입니다. 헤더 이름도 민감할 수 있으므로 결과는 과제 공간 안에 보관합니다.

## 패키지 검증

하네스 폴더에서 실행합니다. 테스트는 임시 폴더의 허구 데이터만 사용합니다.

```sh
python3.11 scripts/check_package.py
python3.11 -m unittest discover -s tests -v
```

검증된 범위와 미확인 사항은 [검증 기록](docs/validation.md)에 있습니다. 실제 제공 Codex의 자동 스킬 탐색·native subagent 지원, 응시환경에서의 동작, 평가 점수 향상은 보장하지 않습니다.

## 제한된 응시환경에서

시험의 최신 안내가 이 문서보다 우선합니다. 제공된 AI와 허용된 모델만 사용하세요. 별도 AI API, 개인 인증정보, 모델 우회, 일반 Computer Use를 요구하지 않습니다. 이전에 전달된 직접 만든 웹사이트의 Playwright 검증 범위는 현재 과제·운영 안내에서 확인한 뒤 적용하며, 응시 플랫폼 조작으로 확대하지 않습니다. 메신저·플랫폼 미리보기·제출은 응시자가 직접 조작합니다. 캡처·영상·trace 저장이나 외부 전송을 이 검증 예외로 허용하지 않습니다.

외부 전송이 금지된 시험에서는 문제, 데이터, 코드, 로그를 외부 서비스·검색 질의·공개 저장소로 보내지 않습니다. 외부 패키지는 설치 스크립트와 데이터 전송 여부를 확인하고 꼭 필요할 때만 사용합니다. 기본 MCP는 없습니다.

작업 중 채운 근거 양식은 시험 작업 공간에만 남깁니다. 후속 서술형 등 AI 금지 단계에서는 하네스 사용을 끝내고 본인이 직접 답합니다. 제출 전 기록은 실제 수행 사실에 한정하며, 예상 문항 답안은 생성하지 않습니다.

## 공개 전 확인

이 폴더에는 재사용 지침, 빈 양식, 허구의 연습 사례만 둡니다. 개인 설정·위키·원본 안내 PDF·메일·응시 링크·스크린샷·시험 자료와 그 원문 발췌는 넣지 않습니다. 공개할 파일과 git 이력을 확인한 뒤 공개합니다. 현재 적용 안내에 따라 사용한 공개 저장소는 결과 통지 전까지 공개 유지합니다.

현재 공개 대상은 [RELEASE_FILES.txt](RELEASE_FILES.txt)에 명시한 파일입니다. 입력 데이터·생성 보고서·인증정보를 추가하지 않습니다. [출처와 배포 범위](SOURCES.md), [MIT License](LICENSE)를 함께 확인하세요. 참고한 upstream 전체 기능을 제공하는 배포판은 아닙니다.

준비 저장소를 유지·배포할 때는 `git add --pathspec-from-file=RELEASE_FILES.txt`로 지정 파일만 추가하고 staged 목록과 전체 커밋 이력을 검토합니다. 패키지 검사기는 모든 최상위 파일이나 비밀값을 탐지하는 도구가 아닙니다. 이 배포 절차는 시험 결과물의 외부 전송을 허용하지 않습니다.
