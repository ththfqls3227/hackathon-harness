# 실행 흐름

하네스 루트의 `AGENTS.md`를 먼저 읽는다. 이 파일 기준 루트는 `../../..`이다. 모든 산출물은 실제 과제 작업 공간에 작성하고 하네스를 과제 정답으로 대체하지 않는다.

## 시작과 시간

- 실제 과제 README·지침·기존 코드와 남은 시간을 확인한다. 실행 방법과 필수 제출물을 추출한다. 모델은 플랫폼에서 허용된 목록 중 선택하며 모델 식별자를 추측하거나 업데이트하지 않는다.
- 런타임·패키지 매니저·테스트 명령을 확인한다. 기존 테스트가 있으면 현재 상태를 확인하고 기존 실패와 변경에 따른 실패를 구별한다.
- 필요하면 `../task-scope/SKILL.md`를 읽는다. 질문 대기 중에는 파일 구조와 데이터를 확인하는 등 답과 독립적인 일을 진행한다.
- 제출에 필요한 시간을 먼저 확보하고 남은 시간을 맥락·범위 확인, 핵심 구현, 검증·수정, 문서 정리에 나눈다. 핵심 구현과 검증에 가장 많은 시간을 쓰되 실제 남은 시간과 운영 공지를 기준으로 조정한다. 절대 마감과 후속 단계 시간을 별도로 확인한다.

## 구현

1. 입력에서 결과까지 가장 작은 흐름을 먼저 완성한다. 과제 종류에 따라 분석 노트북, CLI, 보고서, 웹 서비스 중 적합한 형태를 선택한다.
2. 기능 하나를 붙이면 그 기능의 실제 입력·출력을 검증한다. 기존 테스트 경계가 있으면 재사용하고, 새 테스트는 사용자가 관찰하는 동작을 확인한다. 기대값은 구현식을 복제해서 만들지 말고 요구사항이나 독립 계산에서 얻는다. 오류가 나면 재현 → 원인 가설 → 최소 수정 → 같은 재현 조건 재검증 순서로 진행한다. 여러 가설의 수정을 한꺼번에 섞지 않는다.
3. 외부 도구가 필요하면 기능 공백과 데이터 흐름부터 확인한다. 공개 다운로드 허용은 외부 데이터 전송 허용과 다르다. 외부 AI 호출·원격 저장·자동 브라우저 조작이 필요한 도구는 이 제한 환경의 해법으로 삼지 않는다. 기본 MCP는 설치하지 않는다.
4. 독립 작업과 지원되는 native subagent가 있고 규정상 허용될 때만 위임한다. 요청에는 목표, 최소 맥락, 담당 파일, 금지사항, 검증 기준을 담는다. 공통 파일을 동시에 고치지 않는다. 응답 대기와 병합 비용이 더 크면 혼자 진행한다.
5. 중요한 선택을 했을 때 실제 근거를 필수 문서 또는 `../../../templates/work-evidence.md` 형식에 짧게 기록한다. 사후에 수행하지 않은 검증이나 대화를 만들어 채우지 않는다.

## 검증과 종료

`../task-verify/SKILL.md`로 요구사항과 동작을 대조한다. 시간이 부족하면 선택 기능부터 덜고 필수 기능·오류 수정·제출 확인을 우선한다. 플랫폼 오류는 증상과 시각을 남겨 참가자가 공식 신고 경로로 전달한다. 같은 실패를 이유 없이 반복하거나 차단을 우회하지 않는다.

필수 산출물과 검증 근거가 준비되면 참가자에게 저장·제출 확인 사항을 전달한다. 파일 확정 이후 수정, 제출 자동 조작, AI 금지 단계의 답변은 수행하지 않는다.

## 연습 시나리오

- 정상: 제공 CSV의 오류를 찾는 과제에서 스키마 확인 → 오류 기준 확인 → 작은 검사기 구현 → 정상·오류 입력 검증 → 지정 파일 저장까지 진행한다.
- 실패: 스킬 자동 인식이나 subagent가 없으면 파일을 명시적으로 읽고 단독으로 이어간다. 환경 업데이트로 해결하지 않는다.
- 경계: 공개 저장소 push나 외부 모델 사용이 제안되면 해당 동작을 중단하고 로컬 검증과 허용된 작업을 이어간다.
