# CSV 데이터 점검

실제 과제 지침과 데이터 접근 허용 범위를 먼저 확인한다. 허용된 로컬 CSV만 다루고 외부 전송이나 추가 설치를 하지 않는다. 이 스킬은 데이터의 구조적 상태를 간단히 요약한다. 분석 결과나 업무 성과를 계산하지 않는다.

Python 3.10 이상으로 실행한다. 아래 예시는 **과제 작업 폴더에서** 실행하며, 하네스는 `tools/hackathon-harness`에 있다고 가정한다. 입력과 결과는 과제 작업 폴더에 두고 공개 하네스 저장소 안에 복사하지 않는다.

```sh
python3.11 tools/hackathon-harness/.agents/skills/data-check/profile_csv.py --input ./allowed-input.csv --output ./new-profile.json
```

`--input`은 명시적 파일 경로다. `--output`은 **존재하지 않는** JSON 경로여야 한다. 출력 파일은 만들 때만 열며 기존 파일과 심볼릭 링크를 덮어쓰지 않는다. 검사가 실패하면 출력 파일을 만들지 않는다. 열 너비가 다른 행이 있으면 JSON을 작성하고 종료 코드 1을 반환한다. 정상 검사는 0, 입력·출력·CSV 문법 오류는 2를 반환한다. 오류 메시지는 원본 값과 경로를 포함하지 않는다.

입력은 UTF-8 또는 UTF-8 BOM CSV이며, 인용된 줄바꿈을 지원한다. 파일은 최대 8 MiB, 헤더를 제외한 데이터 레코드는 최대 100,000개다. 빈 헤더나 중복 헤더는 오류다. JSON에는 헤더 이름, 전체·정상·열 너비 오류 행 수, 정상 행의 열별 빈 문자열 개수만 기록한다. 열 너비 오류 행은 빈 셀 집계에서 제외한다. 공백만 있는 셀은 빈 문자열로 세지 않는다. 셀 원문, 예시, 원본 경로는 기록하지 않는다. 헤더 이름 자체가 민감하면 결과 파일의 접근 범위를 제한한다.

도구 자체의 합성 테스트는 하네스 폴더에서 `python3.11 -m unittest discover -s tests -p 'test_csv_profile.py'`로 실행한다. Python 3.10 이상 인터프리터라면 명령의 `python3.11`을 해당 이름으로 바꿀 수 있다. 실행 검증은 Python 3.11에서 했으며 3.10에서의 실행은 별도 확인이 필요하다.
