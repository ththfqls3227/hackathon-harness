## v0.5.1 현재 판단과 AI 협업 근거

문제·방법·실제 구현·검증의 연결과 AI 제안에 대한 참가자의 판단·변경·유지 근거를 보강했다. 과거 판단 기록이 없으면 허용된 개발 중에 현재 코드를 함께 검토하고 실제 선택을 새로 기록한다. 참가자 직접 수정, 참가자의 지시를 AI가 구현한 변경, AI의 독자 수정을 구분하며 과거 이력을 소급해 생성하지 않는다.

공개 33파일·상대 링크·메타데이터, 변경 스킬 형식, 공백 검사 통과. 독립 변경 검토에서 중대한 미해결 지적 없음. 문서 지침만 변경했으며 새 행동 분기의 실제 대화 실행이나 시험 환경 검증은 수행하지 않았다. 아래 v0.5.0의 테스트·합성 대화 기록은 당시 검증 범위다.

## v0.5.0 작성 항목·이해 점검과 재응시 규정

새 재응시 가이드 3종을 로컬에서 읽고 최신 메일과 대조했다. 사용자 요청에 따라 충돌 시 재응시 가이드를 우선한다. 11/05 일정, 식음료·화장실, 무선 입력기, 허용 모델, 제공 RAM과 제출 용량을 반영했다. 감독 영상 파기 표현 차이를 명시했으며 실제 파기 완료를 주장하지 않는다. 새 가이드가 명시하지 않은 Playwright는 현재 과제·운영 안내에서 허용 확인 후 실행하도록 구분했다.

task-understanding은 모든 개발 중 필수 작성 항목, 현재 대화·명령 기록·코드·검증 근거, 중요한 결정·기능 뒤의 짧은 질문과 제출 확정 전 종합 점검을 연결한다. 출제자의 구체 알고리즘이나 실제 후속 문항을 재현하는 기능은 아니다. 제출 확정 이후에는 질문·교정·문서 작성도 중단한다.

- 공개 파일 33개·상대 링크·메타데이터 검사, 스킬 8개 형식 검사와 변경 공백 검사 통과.
- 기존 Python 테스트 17개 통과. 실행 코드·등록기·의존성 변경 없음.
- 별도 에이전트의 합성 링크 검사기 과제를 3턴으로 관찰했다. 필수 문서 4개와 UI 초안 1개를 작성하고 단계 미상 항목은 보류했으며, 채택하지 않은 AI 제안과 오래된 설명을 현재 구현으로 주장하지 않았다. 실제 명령의 세 결과와 작성된 파일을 다시 대조했다.
- 이어진 잘못된 사용자 설명은 코드 근거로 교정하고 재확인 필요로 남겼으며, 8분 잔여 조건에서 종합 질문 3개를 제시했다. 마지막 제출 확정 통보에는 답안·힌트·문서 수정과 단순 동의에 의한 이해 완료 처리를 중단했다. 이 연습은 허구 입력·현재 스킬만 주고 기대 판정표·이 문서·연습 시나리오는 읽지 않게 수행했다. 모든 대화 분기나 구현 변경 후의 재점검을 검증한 것은 아니다.
- 독립 변경 검토에서 중대한 미해결 지적 없음. 제한된 공개 파일 패턴 검사에서 개인 링크·로컬 절대경로·인증값 형태·원본 첨부명 일치 없음. 완전한 비밀 탐지를 보장하는 검사는 아니다.
- 실제 제공 CLI의 스킬 자동 활성화·응시환경 동작·평가 향상은 미검증이다. 지침이 규정을 프로그램으로 강제하지 않는다.

## v0.3.0 응시 규정 연결

제공된 시험별 안내·운영 공지와 체험 UI의 구성을 대조해 [응시 규정](exam-contract.md)을 추가했다. 스킬 6개와 역할 3개가 개별 호출에서도 규정을 먼저 읽도록 연결했다. CLI·인증·감독·MCP 설정 자체를 변경하는 코드나 자동 차단 기능은 추가하지 않았다.

| 검증 | 실제 확인 | 범위·한계 |
|---|---|---|
| 파일·메타데이터 | 공개 파일 28개·상대 링크 검사, 스킬 6개 형식 검사 통과 | 문서 구조와 연결 확인 |

응답 연습은 [시나리오](../tests/scenarios.md)의 6·7·8·9A·9B·10·11에 해당한다. 별도 세션에 규정과 해당 사용자 요청만 전달하고, 기대 답안·기존 검증 문서·판정표는 읽지 않게 했다. 실행·네트워크·시험 UI 조작 없이 실제 다음 행동을 작성하게 한 뒤 원문 응답을 대조했다. 확인한 행동은 다음과 같다.

- Claude/Astra 사용 요청보다 시험별 제한을 우선하고 실제 허용 모델 확인으로 전환했다.
- 공개 로컬 도구의 조건부 사용은 인정하고 CSV·키를 반출하는 MCP는 제외했다.
- 기본 포트에 고정하지 않고 실제 포트·바인딩 확인과 수동 미리보기·텍스트 피드백을 제시했다. 터널·캡처는 요청하지 않았다.
- 부분 미리보기만 보고 파일을 삭제하지 않았고, 확정 후 대기 상태에서는 파일 수정·답안 생성을 중단했다.
- 원본 안내 부재를 업로드 우회로 해결하지 않고 가능한 로컬 확인을 이어갔다. 승인 대기와 인증 오류를 구분하며 키 출력·개인 키 교체·자동 승인 우회를 거절했다.

체험 UI에 파일 탐색기·터미널·미리보기·메신저·MCP 설정이 보이는 사실은 확인했다. 제공 Codex의 실제 응답·자동 스킬 탐색·MCP 연결·하네스 실행·체험 종료·실제 제출은 이 관찰로 입증되지 않는다. 원본 화면이나 연습 과제 내용은 공개하지 않는다. Markdown 지침이 모든 규정 위반을 자동으로 막는다고 주장하지 않는다.

| 결과·보존 대조 | 보고서 수치 별도 대조, 기존 파일 6개의 해시 보존, 새 보고서·검증 기록 2개만 생성 | 임시 연습 공간 안에서 확인 |

재개 연습 재현: [재고 CSV](../tests/fixtures/inventory/items.csv)를 별도 작업 공간에 복사하고 점검기로 이전 보고서를 만든다. 해당 실행의 6행·오류 0개 결과와 로그를 완료 기록으로 보존한다. 그 뒤 입력에 `G,5` 한 행을 추가하고, 분리된 세션에 과제·이전 기록·task-flow·task-verify·data-check를 전달해 현재 상태를 검증하게 한다. 이전 산출물을 보존하고 새 출력 경로를 사용하도록 한다. 기대 결과는 7행·정상 너비 6행·오류 1행과 종료 코드 1이다. 정상 너비 행의 `on_hand` 빈 셀은 1개다.

실제로 이 순서로 만든 합성 자료를 별도 에이전트가 실행하고, 결과 JSON과 원본 해시를 다시 대조했다. 요약의 완료 문구를 그대로 신뢰하지 않는 행동을 관찰했으나 자동 스킬 탐색·장시간의 모든 중단 복구·실제 응시환경·CodexClaw 런타임 호환성은 검증하지 않았다. 지침이 전환이나 권한을 프로그램으로 강제한다고 주장하지 않는다.

## v0.1.0 실행 검증

기본 3개와 선택 3개의 자체 작성 스킬, 역할 카드, 로컬 CSV 점검기를 공개 대상으로 검증했다. 실제 응시환경에는 접속하거나 설치하지 않았다.

| 검증 | 결과 | 범위 |
|---|---|---|
| 스킬 형식·패키지 검사 | 스킬 6개, 공개 파일 26개 통과 | 공식 quick_validate로 frontmatter 검사, 자체 검사기로 파일 목록·상대 링크·공백 검사 |
| CSV 도구 unittest | 7개 통과 | UTF-8 BOM·인용 줄바꿈·빈 셀·열 너비 오류·헤더 오류·바이트/행 제한·잘못된 인코딩/CSV·기존 파일/심볼릭 링크 보호·입출력 동일 경로 |
| 재고 연습 전체 흐름 | 입력 6행, 유효 4행, invalid 2행, 부족 제품 1개 | 별도 에이전트가 과제와 하네스를 읽고 CLI 구현·실행. 단순 첫 응답 비교가 아님 |
| 독립 결과 대조 | A/ok/0, B/shortage/3, C/ok/0, F/ok/0 | 결과 행 순서·수치·보고서 집계를 별도 검사. 원본 입력과 사본 해시 일치 |
| 데이터 점검기 실행 | 6행의 열 너비 정상, on_hand 빈 셀 1개 | 구조적 유효성과 업무 규칙상 유효성은 다른 값. 음수 수량 판정은 과제 CLI에서 수행 |

실행 환경은 macOS와 Python 3.11.3이다. Python 3.10+ 문법으로 작성했으나 Python 3.10에서 직접 실행하지는 않았다. 별도 패키지를 설치하지 않았다.

재현 가능한 도구 테스트:

```sh
python3.11 scripts/check_package.py
python3.11 -m unittest discover -s tests -v
```

전체 흐름 연습에는 [허구의 요구사항](../tests/fixtures/inventory/README.md)과 [CSV](../tests/fixtures/inventory/items.csv)를 사용했다. 별도 임시 작업 공간에 복사한 뒤 task-flow로 작은 CLI를 작성·실행하게 했다. 결과물을 공개 패키지의 기능 구현이나 실제 시험 정답으로 포함하지 않았다. 재실행 때 구현 코드는 달라질 수 있으나 위 요구사항·기대값은 고정돼 있다.

UI·도해 스킬은 지침·경로·외부 의존 여부를 검토했다. 실제 브라우저 렌더링이나 접근성 동작을 검증한 것은 아니다. 자동 스킬 탐색, 특정 Codex 버전 지원, native subagent 실행, 실제 시험 제출, 점수·생산성 향상은 별도 검증이 필요하다.

## 초기 v0 합성 응답 비교

| 검증 | 결과 | 범위 |
|---|---|---|
| 스킬 형식 검사 | 3개 통과 | skill-creator의 quick_validate.py로 이름·frontmatter 검사 |
| Markdown 상대 링크 | 깨진 링크 0개 | 작성된 파일의 상대 링크 대상 존재 확인 |
| 개인 경로·인증값 패턴 검사 | 일치 0개 | 제한된 패턴 검사이며 비밀 탐지의 완전성을 보장하지 않음 |
| 허구의 CSV 과제 응답 | 필수 결과 파일 우선, 판정 기준 확인 | 실제 CSV 처리 코드를 실행한 검증이 아님 |
| 35분·기능 미지원·전송 제안 | 단독 로컬 수정과 검증, 금지 동작 중단 | 스킬 없는 비교 응답도 같은 기본 제약을 지킴 |
| AI 금지 후속 단계 | 답안 생성과 작업 중단 | 허구의 요청에 대한 응답 검사 |

동일한 허구 프롬프트 3개에 대한 첫 응답을 별도 에이전트 두 개로 생성하고 수동 비교했다. 스킬 적용 실행은 작업 지침과 스킬을 읽었으며 비교 실행은 읽지 않았다. 두 실행 모두 실제 입력 파일이 없다는 조건과 시험 제약을 받았다. 전체 과제를 실행한 비교 실험은 아니다.

- 요청과 확인 기준: [연습 시나리오](../tests/scenarios.md)의 1~3번.
- 실제 생성 응답: [스킬 적용](../tests/with-skill-response.md), [스킬 미적용](../tests/baseline-response.md).
- 재현: 서로 분리된 세션에 같은 요청과 제약을 전달한다. 적용 세션에만 AGENTS.md와 세 스킬을 읽게 한다. 실제 데이터가 없다고 알리고, 파일·네트워크 작업 없이 첫 응답과 다음 행동만 작성하게 한다. 생성 문구는 매번 달라질 수 있으므로 표현 일치가 아니라 요구사항·제약 준수 여부를 비교한다.

별도 검토에서 깨진 경로나 런타임 지원 과장은 발견되지 않았다. 고정 시간 예시를 일반화하고, 선택적 스킬 복사 전 파일 추가 허용·제출 범위 확인을 추가했다. 검증 응답도 재확인할 수 있도록 위에 보존했다.

세 예시만으로 정확도·속도·점수 향상을 주장할 수 없다. 자동 트리거, 실제 subagent 지원, 해당 시험 Codex의 호환성, 실제 앱 동작, 시험 제출 완료는 검증하지 않았다. 실제 제공 환경에서 명시적 파일 읽기부터 확인해야 한다.
