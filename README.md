# Hackathon Harness

문제 정의, 범위 선택, 구현, 검증을 짧게 연결하는 한국어 Codex 하네스입니다. 기본 스킬 3개와 선택 스킬 3개, 로컬 CSV 점검 도구를 제공합니다. MIT 라이선스이며 미리 만든 정답이나 특정 앱 템플릿은 포함하지 않습니다.

실행기·MCP·전역 설정 설치 없이 문서를 읽어 시작합니다. CSV 도구만 Python 3.10+가 필요합니다(실행 검증: Python 3.11). 역할 카드는 자동 등록되는 에이전트 설정이 아닙니다.

아래 명령의 `python3.11`은 검증에 사용한 실행 파일명입니다. 제공 환경에서는 `python3 --version` 등으로 확인한 Python 3.10 이상 실행 파일명으로 바꿔 사용합니다. 시험 환경의 Python을 이 문서 때문에 업데이트하지 않습니다.

## 시작

현재 응시 프로필은 **제공된 Codex 전용**입니다. 시작·재개와 개별 스킬 실행 전에 [응시 규정 프로필](docs/exam-contract.md)을 읽습니다. 일반 체험 튜토리얼에 Claude가 나오거나 MCP 탭이 보이더라도 해당 사용의 허용 여부는 시험별 안내로 판단합니다.

먼저 실제 과제 안내에서 공개 저장소 다운로드와 지침·스킬 사용을 허용하는지 확인합니다. 파일·Skill 업로드 차단과 공개 저장소 다운로드 허용은 서로 다른 조건이며, 공개 자료라고 자동으로 허용되는 것은 아닙니다. 충돌하거나 불명확하면 플랫폼 지원 담당에게 확인하고, 차단을 다른 반입 경로로 우회하지 않습니다.

허용된 경로로 저장소를 가져온 뒤, **실제 과제의 작업 폴더에서** 제공된 Codex를 실행합니다. 아래 요청의 경로를 실제 경로로 바꿔 입력합니다.

과제 작업 폴더에서 공개 저장소 다운로드가 허용되는 경우:

```sh
git clone --depth 1 --branch v0.3.0 https://github.com/ththfqls3227/hackathon-harness.git tools/hackathon-harness
```

같은 이름의 폴더가 이미 있으면 내용을 덮어쓰지 않고 기존 자료를 먼저 확인합니다. 태그로 버전을 고정하며 시험 중 최신 버전으로 자동 업데이트하지 않습니다.

> 먼저 과제 README와 기존 AGENTS.md를 읽어. 그다음 `<하네스 경로>/AGENTS.md`, `<하네스 경로>/docs/exam-contract.md`, `<하네스 경로>/.agents/skills/task-flow/SKILL.md`를 읽고 적용해. 하네스의 상대경로는 하네스 폴더 기준이야. 시험별 규정이 일반 튜토리얼보다 우선이고 제공된 Codex만 사용해. 현재 단계·작업 루트·허용 도구·시간·필수 산출물을 짧게 확인한 뒤 최소 구현 범위부터 정리하고 독립적으로 가능한 작업은 진행해.

이 명시적 읽기는 이미 허용된 경로로 작업 공간 안에 가져온 문서를 읽는 방법입니다. 개인 PC 파일 반입이나 Skill 업로드 차단을 우회하는 방법이 아닙니다. 별도 설치, API 키, MCP, Codex 업데이트가 필요하지 않습니다. 기존 과제의 README·AGENTS.md·설정을 덮어쓰지 않습니다.

현재 Codex의 프로젝트 스킬 규약은 `.agents/skills/<name>/SKILL.md`입니다. 실제 제공 버전의 자동 탐색과 규정상 파일 추가 허용을 확인한 경우에만 과제 폴더의 같은 위치에 필요한 스킬을 충돌 없이 복사해 쓸 수 있습니다. 추가 파일이 제출 범위에 포함되는지도 확인하세요. 폴더를 복사했다고 현재 세션에 로드되었다고 단정하지 마세요. 자동 탐색이 안 되면 위처럼 파일을 직접 읽습니다.

| [근거 양식](templates/work-evidence.md) | 사실·판단·검증·미해결 사항을 작업 중 기록 |

| [검증 기록](docs/validation.md) | 확인한 범위와 아직 확인하지 않은 것 |

역할 카드는 사람이 읽거나 지원되는 에이전트에 전달하는 지침입니다. 파일이 존재한다고 subagent가 생성되거나 특정 모델로 실행되는 것은 아닙니다. 기본은 하나의 Codex가 순서대로 진행하는 방식입니다.

v0.2.0은 CodexClaw에서 참고한 계획·사전 검토·구현·검증·정리 흐름, 조건부 경로의 실행 확인, 과제 안의 기록을 이용한 재개를 기존 스킬에 반영했습니다. 작은 수정에는 전체 절차를 강제하지 않습니다. [반영 범위와 제외 이유](docs/codexclaw-review.md)를 확인하세요. CodexClaw 플러그인 설치나 자동 상태 전환 기능은 포함하지 않습니다.

v0.3.0은 응시 규정 프로필을 모든 스킬·역할의 시작점에 연결했습니다. 공개 도구의 허용된 수신과 시험 자료 반출을 구분하고, 화면 캡처 요청·Claude 실행·키 출력·제출 확정 후 작업을 하지 않도록 명시했습니다. 스크린샷에 메뉴가 보인 사실만으로 CLI 실행·MCP 연결·실제 시험 호환성을 검증했다고 주장하지 않습니다.

## 선택 기능 사용

기본은 task-flow 하나로 시작하고, 실제 과제에 맞는 스킬만 추가로 읽습니다.

- CSV가 있으면 data-check로 구조를 확인합니다. 업무 규칙과 성과 분석은 별도로 해야 합니다.
- 화면이 필요하면 ui-review로 정상·빈 데이터·실패 상태와 수동 확인 절차를 정리합니다.
- 설비나 시스템의 관계를 설명해야 하면 system-diagram을 사용합니다. 원본 Anatomy의 키트나 고급 렌더러가 포함된 것은 아닙니다.

CSV 점검 예시도 **과제 작업 폴더에서** 실행합니다. 데이터와 결과를 공개 하네스 폴더 안에 두지 않습니다.

```sh
python3.11 tools/hackathon-harness/.agents/skills/data-check/profile_csv.py --input ./input.csv --output ./profile.json
```

기존 결과를 덮어쓰지 않습니다. 종료 코드는 정상 0, 열 너비 오류가 있는 보고서 1, 입력·출력·문법 오류 2입니다. 헤더 이름도 민감할 수 있으므로 결과는 과제 공간 안에 보관합니다.

## 패키지 검증

하네스 폴더에서 실행합니다. 테스트는 임시 폴더의 허구 데이터만 사용합니다.

```sh
python3.11 scripts/check_package.py
python3.11 -m unittest discover -s tests -v
```

검증된 범위와 미확인 사항은 [검증 기록](docs/validation.md)에 있습니다. 실제 제공 Codex의 자동 스킬 탐색·native subagent 지원, 응시환경에서의 동작, 평가 점수 향상은 보장하지 않습니다.

## 제한된 응시환경에서

시험의 최신 안내가 이 문서보다 우선합니다. 제공된 AI와 허용된 모델만 사용하세요. 별도 AI API, 개인 인증정보, 모델 우회, 감독 설정 변경, Computer Use를 요구하지 않습니다. 메신저와 브라우저 미리보기는 응시자가 직접 조작합니다. 터미널 테스트·HTTP 검증도 과제 규정이 허용한 범위에서만 합니다.

외부 전송이 금지된 시험에서는 문제, 데이터, 코드, 로그를 외부 서비스·검색 질의·공개 저장소로 보내지 않습니다. 외부 패키지는 설치 스크립트와 데이터 전송 여부를 확인하고 꼭 필요할 때만 사용합니다. 기본 MCP는 없습니다.

작업 중 채운 근거 양식은 시험 작업 공간에만 남깁니다. 후속 서술형 등 AI 금지 단계에서는 하네스 사용을 끝내고 본인이 직접 답합니다. 제출 전 기록은 실제 수행 사실에 한정하며, 예상 문항 답안은 생성하지 않습니다.

## 공개 전 확인

이 폴더에는 재사용 지침, 빈 양식, 허구의 연습 사례만 둡니다. 개인 설정·위키·원본 안내 PDF·메일·응시 링크·스크린샷·시험 자료와 그 원문 발췌는 넣지 않습니다. 공개할 파일과 git 이력을 확인한 뒤 공개합니다. 현재 적용 안내에 따라 사용한 공개 저장소는 결과 통지 전까지 공개 유지합니다.

현재 공개 대상은 [RELEASE_FILES.txt](RELEASE_FILES.txt)에 명시한 파일입니다. 입력 데이터·생성 보고서·인증정보를 추가하지 않습니다. [출처와 배포 범위](SOURCES.md), [MIT License](LICENSE)를 함께 확인하세요. 참고한 upstream 전체 기능을 제공하는 배포판은 아닙니다.

준비 저장소를 유지·배포할 때는 `git add --pathspec-from-file=RELEASE_FILES.txt`로 지정 파일만 추가하고 staged 목록과 전체 커밋 이력을 검토합니다. 패키지 검사기는 모든 최상위 파일이나 비밀값을 탐지하는 도구가 아닙니다. 이 배포 절차는 시험 결과물의 외부 전송을 허용하지 않습니다.
