# 설명을 위한 작은 도해

하네스 [AGENTS.md](../../../AGENTS.md)와 [응시 규정](../../../docs/exam-contract.md)을 먼저 읽고 과제 요구사항을 따른다. Anatomy에서 착안한 자체 작성 워크플로우다. Anatomy 원본 키트·CLI·브라우저 검증 도구는 포함하거나 호출하지 않는다.

1. 독자가 이해해야 하는 관계를 정한다. 절차의 순서면 흐름도, 수치 비교면 차트, 실제 부품의 위치와 연결이 중요하면 구조 도해를 선택한다. 입체감 자체를 목표로 삼지 않는다.
2. 확인된 구성요소·연결·방향·명칭과 출처를 먼저 표로 정리한다. 미확인 구조는 생략하거나 가정이라고 표시한다. 반도체·기계라는 주제만으로 실제 설비의 부품이나 작동 원리를 추측하지 않는다.
3. 핵심 구성요소만 담는 평면 SVG부터 만든다. 라벨, 선, 화살표가 겹치지 않도록 배치하고 일관된 시각 규칙과 범례를 쓴다. 과제에서 요구한 파일 형식을 유지한다.
4. 필요한 경우에만 HTML에 SVG를 직접 넣는다. CSS·JS도 파일 안에 포함하고 시스템 글꼴을 사용한다. 원격 폰트·CDN·추적 코드·API·외부 에셋을 추가하지 않는다. 사용자 입력은 텍스트로 삽입하고 `innerHTML`로 실행하지 않는다.
5. 인터랙션은 선택 항목의 설명 표시처럼 이해를 돕는 작은 기능으로 한정한다. 핵심 정보는 JavaScript가 없어도 읽을 수 있게 한다. 키보드로 접근할 수 있는 버튼과 텍스트 설명을 함께 둔다.
6. XML/HTML 구조와 로컬 파일 참조를 검사한다. 직접 만든 웹에 포함된 도해의 버튼·텍스트·반응형 동작은 [web-verify](../web-verify/SKILL.md)의 허용된 Playwright 범위에서 확인할 수 있다. 참가자는 플랫폼 미리보기에서 라벨·연결·가독성을 직접 확인해 텍스트로 알린다. 캡처 요청·외부 렌더링·일반 브라우저 자동화는 하지 않는다. 구조·동작 검사만으로 시각적 검증을 통과했다고 보고하지 않는다.

완료 조건: 도해가 확인된 사실과 일치하고, 설명에 필요한 관계가 보이며, 외부 리소스 없이 열리고, 수동 검토 상태가 명확하다. 이미 해결한 기능의 설명에 도움이 되지 않으면 도해를 추가하지 않는다.
