# 직접 만든 웹사이트 검증

하네스 [AGENTS.md](../../../AGENTS.md)와 [응시 규정](../../../docs/exam-contract.md)을 먼저 읽는다. 2026-11-04 사용자는 자체 웹 검증에 한해 Playwright를 허용한다고 전달했지만, 새 재응시 가이드는 이를 명시하지 않고 Computer Use·자동 조작을 금지한다. **현재 과제·운영 안내에서 자체 웹 Playwright 허용이 확인된 경우에만 실행**한다. 새 가이드만으로 예외가 재확인됐다고 하지 않는다. 미확인이면 단위·HTTP 검사와 참가자의 제공 Browser 미리보기 확인을 계속한다. 제출물 확정·후속 단계에서는 실행하지 않는다.

## 대상과 실행 조건

1. 과제 README·웹 코드·실행 명령·현재 서버 로그를 읽고 **검증할 앱, 정확한 origin(프로토콜·호스트·포트), 핵심 흐름, 기대 결과**를 정한다. 실제로 만든 앱과 연결되지 않은 URL은 사용하지 않는다. 로컬 주소여도 응시 플랫폼·에디터·메신저·도우미·로그인·감독·제출 화면은 대상이 아니다.
2. 기존 package 파일·Playwright 설정·테스트를 확인하고 제공 환경에 이미 있는 실행 경로를 사용한다. 프로젝트의 테스트 명령을 먼저 읽고 실행하며, 원격 패키지를 즉시 받아 실행하는 명령이나 브라우저 자동 설치를 기본값으로 삼지 않는다. 실행 도구·브라우저가 없으면 원인을 기록하고 가능한 단위·HTTP 검사와 참가자의 수동 확인을 이어간다. 테스트 불가를 통과로 바꾸지 않는다.
3. Playwright가 관리하는 새 브라우저 컨텍스트를 사용한다. 기존 로그인 브라우저·CDP·원격 브라우저·개인 프로필·쿠키·인증 저장소에 연결하지 않는다. 테스트 입력은 로컬 합성 자료를 우선하고 앱 내부 테스트 동작에 한정한다.

## 검증 경계

- 앱 내부 버튼 클릭·입력·화면 전환·결과 확인은 허용된 검증에 포함한다. 응시 플랫폼의 제출 버튼과 앱에서 구현한 테스트용 제출 버튼을 구분한다. 실제 외부 발송·결제·외부 계정 동작은 로컬 대역으로 바꾼다.
- 테스트 전 앱의 외부 폰트·CDN·분석·API·WebSocket 연결을 확인한다. 불필요한 원격 요청은 차단하거나 로컬 대역으로 바꾸고, 검증한 앱과 필요한 자체 로컬 API의 정확한 origin만 대상으로 삼는다. 리디렉션·새 탭도 범위를 벗어나면 중단한다.
- 요청 가로채기를 쓸 때는 새 컨텍스트에 탐색 전에 등록하고 URL의 `origin`을 정확히 비교한다. 단순 문자열 prefix나 `localhost` 포함 여부로 허용하지 않는다. HTTP 라우팅만으로 WebSocket·서비스 워커·브라우저 전체 네트워크가 차단된다고 주장하지 않는다. 외부 통신을 분리할 수 없다면 해당 테스트는 미확인으로 남긴다.
- 스크린샷·영상·trace·HAR은 별도 허용이 확인되기 전까지 저장하지 않는다. Playwright Test 설정의 `screenshot: 'off'`, `video: 'off'`, `trace: 'off'`와 기존 fixture·hook의 직접 캡처·기록 호출도 확인한다. CLI의 trace 옵션으로 다시 켜지 않는다. 서비스 워커가 필요 없는 검사에서는 `serviceWorkers: 'block'`을 사용하며, 워커를 막은 상태로 워커 기능을 검증했다고 쓰지 않는다.
- 보고서는 작업 공간의 텍스트 결과와 필요한 실패 정보만 남긴다. 원격 대시보드 업로드·공유 링크·스크린샷 서비스·시험 자료의 외부 전송을 하지 않는다. 이 지침은 네트워크 격리를 강제하는 실행기가 아니다.

## 작은 테스트부터

요구사항에 맞는 핵심 흐름 하나를 먼저 실행한다. role·label·사용자가 보는 텍스트 등 안정적인 선택자와 실제 상태 assertion을 사용하고, 고정 대기만으로 성공을 판단하지 않는다. 이어서 바뀐 기능의 잘못된 입력·빈 데이터·실패 처리와 관련 있는 키보드·좁은 화면 상태를 확인한다. 모든 과제에 같은 테스트 수를 강제하지 않는다.

실패하면 해당 입력·기대값·실제값과 변경 경로를 연결해 최소 수정 후 재실행한다. 테스트 0개·잘못된 서버·이전 빌드의 통과는 현재 결과의 증거가 아니다. 자동 검사가 확인한 동작과 사람이 확인할 미감·가독성·전체 접근성을 구분한다.

최종 결과는 **대상 앱·주소 / 실행 명령 / 검사한 흐름 / 실제 결과 / 미확인과 이유**로 남긴다. 과제 제출 준비는 [task-verify](../task-verify/SKILL.md)로 이어간다.

공식 사용법 참고: [기록 옵션](https://playwright.dev/docs/test-use-options), [브라우저 컨텍스트와 요청 라우팅](https://playwright.dev/docs/api/class-browsercontext), [서비스 워커 제약](https://playwright.dev/docs/service-workers). 실제 제공 버전에서 지원되는 API를 확인하며 도구를 업데이트하지 않는다.
