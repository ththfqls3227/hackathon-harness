# 핵심 흐름을 이해할 수 있는 화면

하네스 루트의 `AGENTS.md`와 실제 과제 요구사항을 따른다. 이 스킬은 자체 작성한 검토 지침이며 외부 디자인 도구나 특정 프레임워크를 설치하지 않는다.

1. 누가 어떤 정보를 보고 어떤 결정을 하는 화면인지 한 문장으로 정한다. 가장 중요한 행동과 결과를 먼저 배치한다. 실제 데이터가 없으면 예시임을 표시하고 성과처럼 보이는 숫자를 만들지 않는다.
2. 기존 디자인이 있으면 글꼴·간격·색상·컴포넌트 규칙을 따른다. 새 화면이면 작은 색상 팔레트, 구분되는 제목/본문, 일관된 간격을 정한다. 화면마다 다른 스타일을 추가하지 않는다.
3. 정상 상태 외에 빈 데이터·로딩·잘못된 입력·실패·성공 상태를 확인한다. 오류는 무엇을 고치면 되는지 알려주며 기존 입력을 불필요하게 지우지 않는다.
4. 코드에서 label과 입력의 연결, 버튼 의미, 키보드 포커스, 표 헤더, 대체 텍스트, 색상 외의 상태 표시를 확인한다. 그래프는 단위·분모·축·기간·표본 범위를 명시하고 오해를 만드는 축 자르기나 장식을 피한다.
5. 제공 플랫폼의 미리보기는 참가자가 직접 사용한다. 핵심 동작 한 번, 오류 입력 한 번, 좁은 화면에서의 배치를 확인할 짧은 절차를 제시한다. 자동 브라우저 조작이나 외부 스크린샷 서비스는 호출하지 않는다.
6. 서버 응답·빌드 성공·코드상 검토·사람이 확인한 화면 동작을 각각 구분한다. 수동 확인을 받기 전에는 접근성이나 화면 동작이 검증됐다고 쓰지 않는다.

출력: 가장 영향이 큰 문제, 해당 코드/화면 위치, 최소 수정안, 확인 결과. 미감 개선 때문에 필수 동작과 제출 준비를 늦추지 않는다. 관련 없는 전체 리디자인은 시작하지 않는다.
